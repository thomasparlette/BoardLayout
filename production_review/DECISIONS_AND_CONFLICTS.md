# R10 decisions and conflicts

## Baseline preservation

The repository's initial commit, `b5af19f6b018b43a92e55f4675a8856e3b85c9b5`, is the immutable supplied baseline. `baseline/SHA256SUMS.txt` hashes every tracked baseline file. A second in-repository copy of the complete project was intentionally not added because Git already preserves the byte-identical baseline and duplicating the 26 MB board would increase review and repository cost without adding recoverability.

## Stale report conflict

The native board text controls object inventory over `reports/Routing_validation.json`. The board contains 43,176 segments and 2,230 vias; the report contains 42,896 and 2,226. The report is therefore historical until regenerated by native KiCad.

## Signal-width conflict

`REQUIREMENTS_CURRENT.md` and `reports/Routing_targets.json` specify a 0.25 mm signal target. The project Default net class remains 0.20 mm and has no dedicated Signal-class assignment. The 0.25 mm requirement controls unless an engineering decision explicitly changes it. No mass width change is authorized before native DRC and route-by-route review.

## Static versus native validation

The standard-library audit is accepted only for file inventory, exact-geometry checks, saved-report comparison, and stored-netlist mapping. Native KiCad remains controlling for connectivity, zone fill, DRC, ERC, library comparison, and manufacturing plots.
